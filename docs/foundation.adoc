= Echo Types — Foundation and Trusted Base
:toc: macro

== Foundation

`Echo f y := Σ (x : A) , (f x ≡ y)` is the standard dependent fibre. The ordinary kernel uses Agda dependent pairs and propositional equality. `EchoFiberTriangulation.agda` compares this definition with standard-library surjection witnesses; it is calibration and orientation coherence, not an independent soundness metatheorem.

== Baseline workflow and profiles

At the audited baseline, the owning source was `.github/workflows/agda.yml`. Its seven roots were:

* `All.agda`
* `Smoke.agda`
* `characteristic/All.agda`
* `examples/All.agda`
* `EchoImageFactorizationPropCubical.agda`
* `experimental/echo-additive/All.agda`
* `NarrowingSmoke.agda`

The ordinary roots use `--safe --without-K --cubical-compatible`. The Cubical root is checked separately with `--safe --cubical`. The cold lane adds `--ignore-interfaces`; the warm lane uses interfaces. A green collection of roots is not a typecheck of every tracked Agda file.

`characteristic/N5Falsifier.agda` is imported by `characteristic/All.agda`; there is no current expected-failure gate. Earlier reports of a deliberately broken excluded N5 describe an earlier state.

`tools/check-guardrails.sh` scans beyond the root closures, but explicitly exempts `EchoImageFactorizationPropPostulated`, `EchoImageFactorizationPropCubical`, and `EchoDecorationBridge`. Thus “every module is safe and postulate-free” is false as a repository-wide claim. The exemptions do not all have the same reason: the Cubical file is safe in its own profile; the postulated and exploratory files carry different trust obligations.

The Cubical file constructs truncation in a separate, self-contained restatement. It does not import the ordinary Echo interface literally. Relating those presentations is a separate boundary obligation.

== Baseline toolchain

The audited baseline CI installs Agda from apt on `ubuntu-latest` and only asserts a 2.x version. Agda and the runner were therefore not exactly pinned in that revision. The standard library checkout at tag `v2.3` is verified against commit `8326c7475af1fa456ca04a0203c168d5d7ff842b`; absolute-zero is checked out and verified at `f486c29903434589117fa0662c6f29b0f17d1d5f`.

The audited baseline contains no reproducible flake-style toolchain pin after the Nix-to-Guix removal (#275), and its workflow contains no corresponding check job. Its echo messages refer to absent facilities. Those were stale workflow prose, not evidence of a reproducible toolchain. Baseline library pins live in `.github/workflows/agda.yml`; its Agda executable is apt-selected. Earlier revision-history entries below record historical claims and do not establish the current files or checks.

The baseline seven-root counts above and the completed local compiler receipts remain evidence about their stated checks, not evidence that the changed GitHub configuration has executed successfully.

The latter replaces the historical Python inventory command; conversion equivalence is checked separately from proof typechecking. `mise.toml` lists Bun and just; Agda setup is handled by the dedicated script.

Run `scripts/kernel-guard.sh`, `tools/check-guardrails.sh`, `scripts/check-experimental-aggregate.sh`, and `scripts/check-agda-invocations.sh` for the separate static checks. A source scan is not a typecheck; a successful remote baseline run is not a fresh local run. The local audit now passes all 15 direct/audit entrypoints and all seven existing roots under Agda 2.7.0.1, plus a fresh `--ignore-interfaces` AuditSmoke check with exit 0. Consult link:audit/2026-11-06-evidence.adoc[the evidence ledger] for receipts, warnings, source identity, current inventory, and the limits of these checks.
