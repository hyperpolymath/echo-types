== Why this module departs from the default profile

The default profile is `--safe --without-K --cubical-compatible`. Under it,
propositional truncation `∥_∥` cannot be constructed, because it is a higher
inductive type. `EchoImageFactorizationPropPostulated` therefore assumes it
through four postulates. Those postulates are a necessary axiom under the
Trusted-Base Reduction Policy (`docs/proof-debt.adoc`).

This module constructs `∥_∥` as a real higher inductive type under
`--cubical`. It proves the four interface obligations, so the (epi, mono)
image factorisation becomes a proof instead of a consequence of assumed laws.

Agda forbids a `--cubical` module from importing a `--without-K` module that is
not `--cubical-compatible`. The module therefore restates `TruncInterface`,
`Echo`, `echo-intro` and the `ImageProp` content locally.

== What the profile establishes, and what it does not

Established when the CI job is green:

* The module type-checks under `--cubical --safe`, so there are no postulates
  and no unsafe pragmas in it. `--safe` rejects a `postulate` under `--cubical`:
  a one-line control module with a postulate exits 42.
* The four truncation obligations and the factorisation are proved in Cubical
  Agda.

Not established:

* *Definitional identity with the `--without-K` originals.* The module's
  header comment says the restated pieces are "definitionally identical" to
  their `--safe --without-K` originals. No tool checks this. It is an argued
  claim, and a reviewer should compare the restated definitions by hand.
* *Membership of the `--without-K` aggregate.* This module is outside that
  aggregate, and nothing proved here transfers to the default-profile modules.
* *Warning-free compatibility.* Agda reports warnings on this module (17 with
  Agda 2.8.0.2 locally). They are `UnsupportedIndexedMatch` notes on transports
  in Cubical Agda, not errors. Triage remains open in `PROOF-STATUS.adoc`.
